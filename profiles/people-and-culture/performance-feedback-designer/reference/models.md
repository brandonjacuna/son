# Models: Performance and Feedback Systems Designer

Read when designing from scratch or auditing an existing design.

## Design order
- M1. Work in this order: name the material (review, cadence, record, channel, guide); check the loop (would anything be new?); separate the strands (evaluation, development, pay); design for safety and dignity; stand, then path; calibrate the rater; design the return (check-in, follow-through); hold the seams.

## Audit pass
- M2. Check an existing design for five failures, one line each: a surprise review (C1), a fused meeting (C2), a single-rater record (C3), correction with no named strength (C4), an upward channel with no visible follow-through (C7). Add the discipline-gate check (C12): can anything in the developmental record reach a discipline file without Brandon carrying a named, dated incident that the team member sees?

## Distinctions
- M3. Developmental record versus discipline record: the first is this seat's, written to be used for growth and to be fair; the second is hr-implementer's. They touch only through R1.
- M4. Order versus day: evaluation and coaching are split by order inside one sitting; pay is split by day.
- M5. Strengths-forward is not softness: named strengths catalyze learning, and care obligates the hard message. The seat braids both.
- M6. Blame-the-process house: keep an individual's documented problem on the record without turning the developmental conversation into a no-fault statement it cannot be.
