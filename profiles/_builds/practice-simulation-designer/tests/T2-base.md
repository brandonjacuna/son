# T2 review: table 12 end-of-module scenario

Verdict: do not put it in as written. It is a recall item with one visible answer, and it asserts service policy the scenario does not source.

## Problems

1. Answer B is the giveaway. It is three times the length of the others and holds every "good service" element. A learner can pass by picking the longest option without reading the situation.
2. A, C and D are strawmen. A is a dismissal, C is neglect, D is a hand-off. No distractor is a plausible good-faith choice, so the item cannot tell a learner who understands the situation from one who can spot the nice answer.
3. D is not clearly wrong. Bringing in a manager is correct if comps need manager approval. The item marks it wrong without saying why.
4. B contains unsourced policy. It assumes a server can comp an item without approval, and that a comp is the right first move. Neither is stated in the scenario or shown to be Sŏn policy. If the module does not teach comp authority, this item tests something it never taught.
5. B has the wrong order. It offers a comp before anyone knows why the ticket is late (fired late, dropped, 86'd item, kitchen backed up). The first step is to find out, then return with a real time. The item skips the step that matters most.
6. B makes commitments the server cannot control: "right away" and "within a few minutes." The correct behavior is to give a time only after checking with the kitchen or expo.
7. "Apologize sincerely" and "so they feel cared for" are not observable actions. They are tone claims, and the second is performed-conviction phrasing. Replace with what the server says and does.
8. "What would you do?" asks for a preference. An end-of-module check should ask for the best action given stated facts.
9. The scenario lacks facts the decision depends on: ticket status, whether the server has already checked in, the 25-minute standard for this restaurant, and who has comp authority. Without them, several answers are defensible.
10. Nothing is Sŏn-specific. It reads as a generic restaurant item, so it does not verify this module or this room. "Customer" is correctly used in the framing, but the item has no Sŏn standard behind it.

## Fix direction

- State the facts: ticket fired 4 minutes ago, kitchen says 6 more minutes, a manager approves comps.
- Make every option something a competent server might do. Differences are in order and timing, not in decency.
- Make options similar in length and form.
- Ask "what do you do first?" and score against the module's stated standard, which must be named in the answer rationale.
- Add a second beat: after the check, the customers ask about the comp. This tests the order.
- Confirm the comp rule and the time-check standard from the module source before writing the key. Do not infer them.

## Open questions for the module owner

- What is the stated wait threshold, and who may comp?
- Which module objective does this item verify?
