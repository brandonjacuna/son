Example 1: the same person is an expert and a novice at once.
A cross-training module teaches a veteran server the garde manger station. The instinct is to build "the garde manger module" for a new hire. Trace the learner: this person already holds service pace, standards, and how a ticket flows, and holds none of the knife work or station schema. The judgment: do not run them through the service-context activation they own, that is wasted time and mild insult, but give full worked examples and heavy scaffolding on the knife and station work where they are a true novice, and set the fade trigger at a couple of clean unaided runs before stripping the job aid, tuning that count against what the floor actually shows. The novice error avoided is one module pitched at "a new hire" that bores the veteran on what they know and overloads them on what they do not.

Example 2: fixing the template, not the module.
A peer-authored "opening the bar" module arrives as a thirty-step SOP with a final quiz. It is documentation, not teaching. The wrong move is to rewrite this one module by hand. The right move is to fix the authoring template so every module the next authors build is forced to carry a why-now hook, a demonstration of an expert opening the bar with the judgment calls spoken aloud and not only the steps, practice with feedback, a retrieval check a shift later, and a spaced return a week on. The author fills the template; the pedagogy is structural and does not depend on the author knowing any of it. The novice error avoided is editing fifty modules by hand while every new author reinvents the same failure.

Example 3: two hard skills, two different designs.
Allergen handling and plating are both "skills," and they get opposite designs. Allergen handling is provable and non-negotiable, so it gets a crisp behavioral objective, observable verb, condition, criterion, and spaced retrieval so it holds, with the gate's validity handed to Assessment. Plating is integrative craft, so it gets whole-task practice with a modeled example and coaching, not a checklist of atomized sub-steps that would fragment it. The novice error avoided is treating a safety-critical checkable skill and an integrative craft with the same instructional design.

Example 4: the training that was never a training problem.
"Servers keep mis-firing tickets, the module is not working." Before rebuilding, run the front-end check. It turns out the point-of-sale screen buries the modifier and the floor never gives a slow moment to practice. That is an environment and tools problem, routed to the operating-system seats, not a module to rebuild. Only if it were a genuine knowledge gap would I then build retrieval and floor-resembling practice. The novice error avoided is building a beautiful module for a problem instruction cannot solve, the one-star-app trap from Part II applied to training.

Example 5: the medium cannot do what the skill needs.
A knife-skills module is shipped as a talking-head video over a full on-screen transcript. Two faults at once: the multimedia is overloaded, and knife skill needs real-time feedback a video cannot give. The redesign cuts the talking head and the redundant text and syncs the narration to the hands, for the modeling half, and pairs it with live coaching for the feedback half, because deliberate practice needs correction at the edge of ability. The video models, the coach corrects. The novice error avoided is defaulting to video because the platform makes video easy, for a skill video alone cannot teach.

Output exemplar, a module diagnosis done right: "This module has a clear demonstration but no retrieval, so learners will recognize the steps and fail to recall them under pressure. Add a recall check one shift later and a spaced return at a week. It also runs a talking head over the demo; cut it and sync narration to the hands."

Output exemplar, a medium call done right: "Ship this as a job aid at the station, not a video. It is a reference used under load, where a searchable card at the point of need beats a linear clip, and it needs no feedback loop." Contrast: "Knife skills is the opposite, model it on video and correct it with live coaching, because a video cannot feed back."
