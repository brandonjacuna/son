# Operations Space Audit (90136733940)

## Summary

Operations is almost entirely one thing: the **Carryover Register** (901327884538), a 126-task capture log for a "Scaling People: Sŏn Operational Build Out" translation program — a session-by-session (S1–S17+) effort to turn some external framework/book ("her" — an unnamed author/consultant, referenced repeatedly) into Sŏn's own operating system, canon, and charter documents. A second list, **Operations Capture** (901327291225, 8 tasks), is the generic idea-inbox pattern used across every space in the workspace. The **Operations Documents** folder holds no lists/tasks — it's pure Docs storage (16 pages across 4 docs: *Sŏn Operating System*, *Scaling People: Translation Program*, *Founder Bios*, and a 10-page *Operating Agreement — Founder Pre-Counsel Brief*, several sections marked "Dominic Review Required" / "Attorney Review Required").

This space today functions as Brandon's personal working ledger for building the People/Operations "canon," not as an execution or task-tracking space. It has essentially none of the mechanics of project management: no assignees, no due dates, no tags, no checklists, no subtasks, and only 2 of ~134 tasks carry any custom field data.

## Details

**Lists**
- Carryover Register — 126 tasks, all status "to do" (single open status; 7 other statuses defined — planning/in progress/at risk/update required/on hold/complete/cancelled — but zero tasks use any of them).
- Operations Capture — 8 tasks, all status "revist" (its open status; planning/in progress/complete/cancelled also defined and unused).
- Operations Documents (folder) — 0 tasks; 4 docs / 16 pages.

**Statuses**: Both lists carry the same generic 5–8 status set (to do/revist, planning, in progress, at risk, update required, on hold, complete, cancelled) — space-level template, not customized per list purpose, and not actually used beyond the default open status.

**Custom fields**: Carryover Register has none. Operations Capture has the workspace-wide Capture template — "Category" (labels: Asset Digital/Physical, Function, Idea) and "Notes" (text), created 2025-06-08 — but on every sampled task both are empty.

**Task content**: Carryover Register task names and descriptions are dense, internally-cross-referenced prose (e.g. "Rows 119 to 129, the conditions layer on the map, seven instrument extensions..."), written in a bespoke shorthand — session codes (S5, S17), paragraph/item codes (P45, I14, A20), and inline links to other task IDs (`86ajgmk27`) and a specific Doc page (`Sŏn Operating System`, doc id `2ky45bmy-17253`). Effectively each task is one findings/routing entry in a manually-maintained knowledge graph, not an actionable to-do. Descriptions run several sentences to a paragraph; titles alone are often incomprehensible without the description. Operations Capture and People Capture tasks, by contrast, have empty descriptions and short plain-English titles ("Build employee library and knowledge center") — genuine backlog items.

**Assignees/due dates/priority/tags**: No assignees anywhere (creator is always Brandon). No due dates anywhere. Tags: none in use. Priority is set (mostly high/urgent, some normal) on Carryover Register "to do" items but always null on Operations Capture "revist" items — priority appears to correlate with list/status rather than being deliberately triaged.

**Subtasks/checklists**: None found in any sampled task (0 subtasks, 0 checklist items) despite descriptions that read like structured lists of sub-items — checklist functionality isn't being used at all.

**Docs**: Operations Documents folder contains: *Sŏn Operating System* (the session-by-session canon, pages named "S8: Team structures...", "S10: Creating the team environment..." etc. — mirrors the Carryover Register content), *Scaling People: Translation Program* (program map/session tracker), *Founder Bios* (Brandon page confirmed, presumably Dominic too), and *Operating Agreement — Founder Pre-Counsel Brief* (a working legal doc, several sections explicitly flagged for Dominic's or an attorney's review — sensitive/incomplete legal content living in Docs).

## Issues / opportunities

- **Carryover Register is not a task list** — it's a running notes/findings ledger with zero throughput signal (nothing ever leaves "to do"). If it's meant to feed the eventual restructure (custom task types, statuses, Owner field), it will need a real triage pass — right now there's no way to tell what's resolved, superseded, or still live except by reading each description.
- **Elaborate status workflows are dead weight**: both lists define 5–8 statuses; only the default "to do"/"revist" status is ever used. Either these lists were seeded from a template never adopted, or status-tracking simply hasn't started yet.
- **Capture-list custom fields (Category, Notes) are unused** on every sampled task — same pattern likely holds workspace-wide since it's a shared template.
- **No ownership, no dates, no tags anywhere** — nothing here would survive contact with the planned Owner column / Teams / filtered views without a manual pass to assign owners and classify each item.
- **The Founder Pre-Counsel Brief doc lives inside Operations Documents** alongside working canon notes — worth confirming that's the intended, appropriately-restricted home for legal content mid-negotiation ("Dominic Review Required" / "Attorney Review Required" sections are still open).
- **Dense cross-referencing (task IDs, doc page names, session codes) is doing real structural work** but only inside free-text descriptions — nothing is a ClickUp relationship/dependency field, so it's invisible to filters, views, or search facets, and it will break silently if any referenced task is ever deleted or renamed.
- 100+ single-purpose tasks with no assignee/date/tag is exactly the shape that gets worse, not better, without the Classification field and filtered views the founders want — Operations is a strong first candidate for that rollout.
