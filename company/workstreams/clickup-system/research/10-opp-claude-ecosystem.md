# Claude-Side Leverage — Opportunity Sweep
Researched 2026-09-16. Track: claude-ecosystem. Scope: what Claude itself can do for Sŏn beyond the Meetings system — Skills, scheduled tasks/Routines, Cowork/plugins, connectors (ClickUp, Box, Drive/Gmail/Calendar, Granola, Bear), cross-tool knowledge flows, and the local `/Users/brandonacuna/ClickUp` folder as config-as-code. Builds on `04-claude-side.md` (Routines/connector mechanics for the Meetings system) — this file does not re-derive those, only cites them.

Confidence key: **CONFIRMED** = vendor docs or fetched pages. **UNCERTAIN** = community/inferred/changing-fast.

---

## Key findings

1. **CONFIRMED — custom Agent Skills are the right vehicle for repeatable Sŏn documents.** A Skill is a folder with `SKILL.md` (YAML frontmatter + Markdown instructions, optional scripts/references), stored at `~/.claude/skills/<name>/` (personal, this machine only) or `.claude/skills/<name>/` (project, shared if committed to the local folder/repo). Claude auto-invokes a skill when its `description` matches the request, or you invoke explicitly with `/skill-name`. [code.claude.com/docs/en/skills](https://code.claude.com/docs/en/skills)
2. **CONFIRMED — skill cost is controllable.** Only the short `description` (~200 chars) loads into every turn; full skill content loads only on invocation and then persists in context. Set `disable-model-invocation: true` on skills that should only fire when explicitly called (e.g., a hygiene-audit skill you don't want Claude guessing into) to avoid wasted auto-triggers. [code.claude.com/docs/en/skills](https://code.claude.com/docs/en/skills)
3. **CONFIRMED — three concrete Sŏn skills map directly to this project's own artifacts:** an investor-update-drafting skill (style/structure rules + pulls from the fundraising Classification view), a Scaling-People-to-SOP skill (reads book excerpts already being extracted in Code, outputs a workflow doc in Sŏn's house format), and a ClickUp-hygiene-audit skill (the exact pattern this Phase 1/2 research session has been running manually — read-only sweep, feasibility/risk table output). All three are plausible today with this session's existing ClickUp MCP tools; no new connector needed.
4. **CONFIRMED — three distinct Claude scheduling surfaces exist, already documented in `04-claude-side.md`**: Cloud Routines (survives laptop off, min 1hr interval, account-level connectors only, no approval prompts), Desktop scheduled tasks (skips runs if machine asleep, local file access), and `/loop` (session-scoped). For a **weekly workspace health report** or **stale-task sweep**, the choice mirrors the Meetings-system logic in `04`: use a Cloud Routine if it must run unattended and reliably; Desktop scheduled task is acceptable only if Brandon's laptop is reliably on/awake at the run time and the check is not safety-critical.
5. **CONFIRMED — scheduled-task/Routine access is plan-gated and metered against normal usage, not a separate credit pool.** Max, Team Premium, and Enterprise "premium seats" get scheduled tasks up to 50% of weekly usage limits included; Pro and Team Standard get it only by drawing on usage credits billed at API rates. A previously-announced split of programmatic/scheduled usage into its own credit pool was paused before shipping — "for now, nothing has changed." [support.claude.com/manage-usage-credits](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans), [truefoundry.com/blog/claude-code-limits-explained](https://www.truefoundry.com/blog/claude-code-limits-explained) — **UNCERTAIN** exactly how a weekly ClickUp-hygiene Routine's usage nets against Brandon's specific plan; check current plan tier before committing to a weekly cadence.
6. **CONFIRMED — this session's own `scheduled-tasks` MCP tool (`mcp__scheduled-tasks__*`) is a live, already-available surface** for exactly this: `create_scheduled_task`, `list_scheduled_tasks`, `run_scheduled_task`, `list_task_runs`, `update_scheduled_task`, `delete_scheduled_task`. This is distinct from (and possibly simpler than) a full Claude Cloud Routine — it is the Claude Code CLI's own scheduling surface, usable directly from this environment without setting up a separate claude.ai Routine or GitHub repo. Worth testing for the weekly health report before standing up a Routine.
7. **CONFIRMED — Claude Cowork (the no-code, goal-oriented sibling of Claude Code) ships Plugins**: a plugin bundles skills + connectors + slash commands + sub-agents into a role-specific specialist (HR, legal, finance, ops, etc.). 11 open-source plugins launched 2026-01-30; expanded 2026-02-24 with 9 more knowledge-work/financial plugins, 3 partner plugins, 12 new connectors, and enterprise private-marketplace support for admins. Plugin support is "available today as a research preview for all paid Claude users." [claude.com/blog/cowork-plugins](https://claude.com/blog/cowork-plugins), [reworked.co](https://www.reworked.co/collaboration-productivity/anthropic-adds-plugins-to-claude-cowork/), [constellationr.com](https://www.constellationr.com/insights/news/anthropic-expands-cowork-plugins-across-enterprise-functions)
8. **CONFIRMED — Cowork plan floor is Pro ($20/mo), but real usage needs Max.** Cowork is bundled free into every paid plan (Pro/Max/Team/Enterprise) — no separate Cowork charge — but Pro's usage ceiling makes Max 5x ($100/mo) "the realistic floor" once Cowork runs daily or on a schedule, per third-party cost-tracking writeups (not an official Anthropic claim, treat as **UNCERTAIN** directional guidance). [suprmind.ai/hub/claude/pricing](https://suprmind.ai/hub/claude/pricing/), [automatonagency.com/insights/claude-cowork-pricing](https://automatonagency.com/insights/claude-cowork-pricing)
9. **UNCERTAIN — Cowork reliability complaints are real and recent enough to matter for a 2-3-person founder team with no IT buffer.** Community writeups report: connectors (Drive, Calendar) intermittently failing to authenticate or timing out on large folders; heavy token burn from Cowork re-reading files into context (one user reported ~$50 of credits burned in an afternoon); and one high-profile incident of Cowork deleting ~11GB of files after being asked to "clean up" a folder, interpreting "clean up" more aggressively than intended. Cowork is explicitly still a "research preview." [coworkstack.ai/blog/claude-cowork-reddit](https://coworkstack.ai/blog/claude-cowork-reddit/), [coworkhow.com/guides/user-feedback-summary](https://www.coworkhow.com/guides/user-feedback-summary) — **Implication: do not point Cowork at Scaling People, the Carryover Register, or anything irreversible without explicit per-action review**, mirroring this project's own STRICTLY READ-ONLY ClickUp rule.
10. **CONFIRMED — a first-party ClickUp connector already exists and is scoped narrower than what this research session's own ClickUp MCP tools expose** (per `04-claude-side.md` #8-9): official is OAuth-only, 6 tools, no delete, no custom-field creation. A Cowork "ops" plugin or a scheduled hygiene-sweep task built for Sŏn should assume the narrower official surface unless it explicitly reuses this session's broader connector — confirm which one any given automation actually has before assuming write capability.
11. **CONFIRMED — Box has an official Anthropic connector** (`claude.com/connectors/box`), built on Box's own hosted MCP server (`box.com/mcp-server`), enabling search, multi-file analysis, and metadata extraction across Box content with existing Box permissions respected. [claude.com/connectors/box](https://claude.com/connectors/box), [buildfastwithai.com/blogs/claude-connectors-creative-tools-2026](https://www.buildfastwithai.com/blogs/claude-connectors-creative-tools-2026)
12. **UNCERTAIN — Box connector plan-tier scoping is muddy in current write-ups.** One source states the "standard connector works with your normal Claude access" (i.e., not Team/Enterprise-exclusive), while richer Box AI Q&A/Hubs/governance features are Enterprise-tier — but no primary Anthropic pricing page was found confirming Pro-tier availability specifically; verify live in Brandon's claude.ai connector settings before designing a workflow around it. [aitoolsreview.co.uk/insights/box-claude-connector](https://aitoolsreview.co.uk/insights/box-claude-connector)
13. **CONFIRMED — Bear (the macOS/iOS notes app) shipped a native Claude Connector and MCP server in Bear 2.8 (April 2026)**: one-click Claude Connector setup from inside Bear (no config files), plus a standalone MCP server for Claude Code/other MCP clients, plus a `BearCLI` for scripting. This is directly relevant if either founder keeps informal notes in Bear that should be queryable from Claude or flow into ClickUp Docs. [blog.bear.app/2026/04](https://blog.bear.app/2026/04/bear-2-8-bearcli-claude-connector-and-mcp-server/), [github.com/vasylenko/bear-notes-mcp](https://github.com/vasylenko/bear-notes-mcp)
14. **CONFIRMED — ClickUp Brain's own Connected Search already reaches Box, Google Drive, Dropbox, Confluence, Figma, GitHub, Slack, Notion, Gmail** (per `01-clickup-ai.md` #8 and this search's confirmation), with the same Google-Drive format caveat already flagged there (plain text/HTML/CSV/PDF only, not native Docs/Sheets). This means **Box↔ClickUp↔Brain is a native ClickUp path that needs no Claude connector at all** — the open question is whether it's turned on and whether it's workspace-wide vs. personal-only. [workmanagementhub.com](https://workmanagementhub.com/clickup-brain-ai-complete-guide-2026/) — **UNCERTAIN** whether native Google Docs/Sheets indexing gap has closed in 2026; re-verify live.
15. **CONFIRMED — this project's own `/Users/brandonacuna/ClickUp` folder is already functioning as a config-as-code source of truth**, and this is a documented, common Claude Code pattern: CLAUDE.md/STATE.md/DECISIONS.md as a short, high-signal index loaded every session, with subdirectories (research/, audit/, blueprint/, templates/, runbooks/, logs/) as the durable record — exactly the "thin index + organized subdirectories" pattern community write-ups recommend, and exactly what this project already does. The main risk called out in that literature: bloated instruction files cause Claude to start ignoring real instructions — keep STATE.md/DECISIONS.md terse as they grow. [claudecodeguide.dev/docs/foundations/claude-md](https://claudecodeguide.dev/docs/foundations/claude-md), [prompt-architects.com](https://prompt-architects.com/blog/275-claude-md-templates-for-claude-code)
16. **CONFIRMED — this local folder is not currently a git repo** (session environment metadata: "Is a git repository: false"). That's a gap against the config-as-code pattern: no version history, no diff-based review of DECISIONS.md changes, no way to roll back a bad edit, and no clean mechanism to commit `.mcp.json`/skills so a Cloud Routine could pick them up (per `04-claude-side.md` #5, Routines need connectors/skills committed to a cloned repo). **Recommendation: `git init` this folder once Brandon approves**, even as a local-only repo initially.
17. **CONFIRMED — ClickUp's own automation can flag stale tasks natively** (status-based automation after N days idle), and ClickUp Brain can scan/categorize and turn cleanup into assigned tasks — meaning a "stale-task sweep" does **not necessarily need Claude at all** if ClickUp's native automation + Brain covers it. Claude's edge is cross-space judgment (e.g., "this task duplicates that one," "this SaaS Map row is a duplicate vendor") that simple idle-day automations can't do. [clickup.com/blog/clickup-task-automation-to-eliminate-manual-project-updates](https://clickup.com/blog/clickup-task-automation-to-eliminate-manual-project-updates/)
18. **CONFIRMED — model tiering guidance from `04-claude-side.md` #13 carries over directly**: Sonnet 5 ($2/$10 per M tok) is the right default for a weekly health-report or stale-task-sweep job (structured, well-specified, multi-tool read/summarize). Reserve Opus 5 ($5/$25) only if a synthesis step (e.g., SOP-writing from Scaling People, investor-update drafting) proves to need it after a Sonnet 5 pass looks thin — consistent with this project's own **Fable reserved for synthesis/architecture, sweeps on cheaper models** decision (DECISIONS.md 2026-09-16).

## Detailed notes

### Skills — three concrete candidates for Sŏn
| Skill | Trigger | Reads | Writes | Model |
|---|---|---|---|---|
| Investor-update drafting | On request or scheduled (pre-board-meeting) | Fundraising Classification view, pipeline metrics, last update's diff | Draft only — human sends | Sonnet 5, escalate to Opus if tone/precision falls short |
| Scaling-People → SOP writer | On request, per chapter as Brandon extracts it in Code | Book excerpt + existing Operating System Doc structure | Draft SOP page — human places it | Sonnet 5 |
| ClickUp hygiene audit | Weekly scheduled OR on request | Read-only ClickUp MCP sweep (same posture as this research session) | A report (Doc or file), never a ClickUp write | Sonnet 5 (mirrors this session's own effort) |

All three can be built as project skills in `.claude/skills/` inside this local folder once it's a git repo (finding #16), making them shared and versioned rather than personal-machine-only.

### Scheduled weekly health report / stale-task sweep — build options, ranked
1. **This session's `scheduled-tasks` MCP tool** (finding #6) — lowest friction, no new repo/Routine setup, but confirm it persists/fires reliably when this Claude Code session/window isn't open (behavior not fully verified here — test before relying on it).
2. **Claude Cloud Routine** (per `04-claude-side.md`) — most reliable (survives laptop off), but needs a GitHub repo and claude.ai account-level connectors; heavier setup for a read-only report than it's worth unless it's bundled with the Meetings Routine's infrastructure.
3. **ClickUp-native stale-task automation** (finding #17) — zero Claude cost, but no cross-space judgment; good as a first layer (e.g., flag anything untouched 14+ days), with Claude doing a monthly deeper pass instead of weekly.
Recommendation: start with ClickUp-native staleness flags as the cheap always-on layer, and use option 1 or 2 for a monthly (not weekly) deeper Claude pass — matches the "AI on rollover credits, turn on per use case, keep deliberate" constraint in STATE.md/DECISIONS.md.

### Cross-tool knowledge flows
- **Box ↔ ClickUp Docs ↔ Brain**: native ClickUp Connected Search already reaches Box (finding #14) — this is the cheapest path if Sŏn's legal/lease documents end up in Box, since it needs no Claude connector setup at all, only confirming the connection is turned on and workspace-wide.
- **Box ↔ Claude directly**: useful specifically for tasks Claude does *outside* ClickUp — e.g., an investor-update skill pulling supporting documents from Box that aren't (and shouldn't be) duplicated into ClickUp.
- **Bear ↔ Claude**: relevant only if either founder is already using Bear informally; if not, this is a non-issue — don't introduce a new tool for its own sake.
- **Granola ↔ ClickUp Docs ↔ Brain**: already covered in depth in `04-claude-side.md` (findings #6, #9) — the meeting-notes pipeline is the proven template for any future "external tool → ClickUp Doc → Brain-searchable" flow (Box or otherwise).

### Local folder as config-as-code
- Current state: `/Users/brandonacuna/ClickUp` (STATE.md, DECISIONS.md, ROADMAP.md, research/, audit/, blueprint/, templates/, runbooks/, logs/) already matches the community-recommended shape — a short, current index plus durable subdirectories.
- Gap: not a git repo (finding #16). Fixing this is a prerequisite for (a) any Cloud Routine that needs to clone project skills/config, (b) safe rollback of DECISIONS.md, (c) sharing skills with Dominic/the 3rd partner via a shared remote later.
- This folder is also the natural home for **field specs and taxonomy as text** (e.g., the eventual Classification dropdown value list, task-type definitions) before they're applied in the ClickUp UI — giving Claude a reviewable draft to work from and Brandon a diff to approve, consistent with the workflow this whole project already uses (STATE.md/DECISIONS.md as the log, blueprint/ as the destination).

## Gotchas / limits

- Cowork's research-preview reliability issues (finding #9) — file/connector deletion risk, auth flakiness, token burn — argue for keeping any Sŏn-facing Cowork plugin strictly read-only/draft-only for now, same posture as this research track.
- Scheduled-task/Routine usage draws from the normal plan's usage limits/credits, not a separate free pool (finding #5) — a weekly health report is cheap, but stacking it with the Meetings Routine and ad hoc Claude Code sessions on the same account could matter on Pro; check current plan tier.
- Official ClickUp connector (6 tools, no delete, no field creation) is narrower than this session's own ClickUp MCP (finding #10) — any Sŏn-built skill or plugin must not assume this session's capabilities are universally available.
- Box connector plan-tier availability is not confirmed from a primary source (finding #12) — verify live before designing around it.
- Google Drive/Box format limits on ClickUp Connected Search (plain text/HTML/CSV/PDF; native Docs/Sheets unconfirmed for 2026) carry over from `01-clickup-ai.md` and apply equally to any Box documents kept as native Office/Google formats.
