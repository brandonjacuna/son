Sources dated 2026 where possible; ClickUp's public help/feedback pages returned HTTP 403 to direct fetch, so content below is drawn from search-result snippets of those same URLs (cited) plus third-party summaries — treat article-body wording as paraphrase, not verbatim quote, and spot-check anything decision-critical against the live page before the blueprint locks._

## 1. Super Agents + custom external MCP servers

**CONFIRMED — shipped, general availability path.** ClickUp's "Connect an MCP server to your Workspace" feature lets Super Agents and Brain use tools from any external MCP server. On a Super Agent's profile, the Skills section has an **"Add tools"** button that lists tools from any MCP server you've connected. Feature request [Super Agent Access to MCP Servers](https://feedback.clickup.com/ai-super-agents/p/super-agent-access-to-mcp-servers) shows status moved planned (Mar 2026) → "building now" (Mar 24, 2026) → **shipped Jul 1, 2026**, confirmed by a ClickUp PM (Arkady Sokolov) in-thread. Source: [help.clickup.com/.../38503227973655](https://help.clickup.com/hc/en-us/articles/38503227973655-Connect-an-MCP-server-to-your-Workspace), [feedback.clickup.com](https://feedback.clickup.com/ai-super-agents/p/super-agent-access-to-mcp-servers).

**Auth types — CONFIRMED, three methods.** When connecting a custom MCP server you choose from **OAuth** (redirected to the provider's flow, returned to ClickUp — some providers require pre-registering a callback URL, which ClickUp says should be `https://search.clickup-prod.com/connect/mcp`), **API token**, or **custom headers** (you enter arbitrary header key/value pairs — check with the MCP provider which headers/auth scheme they expect and mirror them). Advanced configuration also exposes Client ID / Client Secret / Scopes fields for OAuth setups. Source: [help.clickup.com/.../38503227973655](https://help.clickup.com/hc/en-us/articles/38503227973655-Connect-an-MCP-server-to-your-Workspace).

**Per-user vs workspace-wide — CONFIRMED, both options exist.**
- **"Just for me" (personal connection):** you link your own account to the external MCP server; only you can use those tools in Super Agents/Brain. Members can set these up if admins allow personal connections.
- **"For all members" (Workspace connection):** only Workspace owners/admins can create these; every member can then use the tools in Super Agents/Brain.
MCP servers must expose a public URL to connect. Source: [help.clickup.com/.../38503227973655](https://help.clickup.com/hc/en-us/articles/38503227973655-Connect-an-MCP-server-to-your-Workspace).

For a small 2–3-founder workspace like Sŏn, a **Workspace connection** set up by Brandon (as owner/admin) is the simpler choice — no per-founder OAuth re-auth needed — but note it means every founder's Super Agents can invoke those tools, so scope the external server's own permissions (e.g., a read/write-limited Google Calendar) accordingly.

**Availability/pricing — CONFIRMED for now, UNCERTAIN long-term.** "For a limited time, all plans can connect to external MCP servers. Pricing may be subject to change in the future" — i.e., no plan-tier gate today, but ClickUp has flagged this could change. Source: same help article (search snippet).

**Credit cost per external tool call — UNCERTAIN, not documented as a distinct line item.** ClickUp's credit-consumption docs describe Super Agent cost only at the level of "an Agent run" (100–300 Super Credits depending on complexity/steps), not broken out per external-MCP-tool-call vs native-tool-call. Assume an external tool call is billed as part of whatever run/step it's in; no separate "external MCP surcharge" was found in any 2026 source. Source: [help.clickup.com/.../37837088720151 "How are AI Super Credits consumed"](https://help.clickup.com/hc/en-us/articles/37837088720151-How-are-AI-Super-Credits-consumed) (search snippet); cost figures corroborated by third-party breakdown in §5 below.

**Reliability — CONFIRMED some early breakage, later resolved; UNCERTAIN steady-state.** In the feedback thread, a user (Jason Joseph) reported "the perpetually breaking MCP connector experience I've been having and flagged yesterday via multiple emails" shortly after ship, then confirmed ClickUp's team resolved it and praised their responsiveness. No broader Reddit/forum corroboration was found (a `site:reddit.com` search for "ClickUp Super Agent" returned no relevant threads — r/clickup discussion on this specific feature appears thin as of Sept 2026, which is itself worth flagging as low community-validation). Separately, ClickUp's own first-party MCP server (a different thing — for external AI clients like Claude to read ClickUp, not for Super Agents to read external services) has an open GitHub-sourced bug report of null-handling issues where "Available workspaces" returns empty. That bug is on the *inbound* MCP server, not the *outbound* connector Super Agents use, so it's only weak signal. Sources: [feedback.clickup.com](https://feedback.clickup.com/ai-super-agents/p/super-agent-access-to-mcp-servers); general MCP-ecosystem reliability search, no ClickUp-specific Reddit thread found.

**Granola's official MCP — CONFIRMED it exists and is connectable in principle.** Granola ships an official **remote/hosted MCP server** at `https://mcp.granola.ai/mcp`, using OAuth (Dynamic Client Registration; also supports Enterprise-Managed Authorization). Any MCP-compatible client (explicitly including "Claude Code, Codex, Cursor, VS Code" per Granola's own docs) can add that endpoint. Its tool surface is **read/search-oriented**: search meeting notes, find topics, browse folders, extract action items/decisions, answer questions from meeting history — i.e., it is built to let an agent *pull* Granola meeting content, not to control Granola itself. Sources: [mcpservers.org/remote-mcp-servers/granola](https://mcpservers.org/remote-mcp-servers/granola), [docs.granola.ai/help-center/sharing/integrations/mcp](https://docs.granola.ai/help-center/sharing/integrations/mcp).
- **UNCERTAIN:** whether a ClickUp Super Agent specifically (vs. a generic MCP client like Claude Code) has actually been connected to `mcp.granola.ai` by anyone publicly — no case study, forum post, or ClickUp doc mentioning "Granola" was found. Since ClickUp's connector supports OAuth and Granola's server uses OAuth/DCR, it is plausible it would work, but this is an inference, not a confirmed integration. **Recommend a hands-on smoke test** (connect Granola's MCP URL as a personal or workspace connection, add its tools to a test Super Agent, try a "find the summary from our last standup" prompt) before relying on it in the blueprint — this dovetails with the "Granola phone-call quality test on Thursday" already on STATE.md.

**Google Calendar MCP for Super Agents — CONFIRMED two paths exist, with an important distinction:**
1. **ClickUp's own native Google Calendar integration**, surfaced to Brain/Agents once you connect your Google account: "After connecting your account, you can use Google Calendar tools in Brain and Agents." A Super Agent can also be given "External Search" access to Google Calendar in its profile. Separately, ClickUp's **Planner** UI lets a human create an event with a name, time/duration, **video call provider including Google Meet**, a **location**, and **Add participants** (search/select guests one at a time). ClickUp's Google Calendar **Automations** (a different subsystem, trigger/action based) can create/update/delete Google Calendar events. Sources: [help.clickup.com/.../6336507264663](https://help.clickup.com/hc/en-us/articles/6336507264663-Google-Calendar-integration), [help.clickup.com/.../35975552416023 Planner](https://help.clickup.com/hc/en-us/articles/35975552416023-Create-events-and-schedule-meetings-from-your-Planner), [help.clickup.com/.../29626553900951 Automations](https://help.clickup.com/hc/en-us/articles/29626553900951-Google-Calendar-Automations).
   - **UNCERTAIN:** whether the *native* "Google Calendar tools in Brain and Agents" tool-set (as distinct from Planner's human UI and from Automations) actually exposes create/update/delete-with-guests-and-Meet-link as callable Super Agent tools, or is limited to read/search ("External Search"). This is the single most decision-relevant unknown for the calendar-agent design and is not resolved by any source found — recommend testing directly: open a test Super Agent's "Add tools" panel and check whether a native Google Calendar tool group appears alongside (or instead of) needing an external MCP.
2. **External community Google Calendar MCP servers** — several exist on GitHub with explicit support for creating events with attendees + Google Meet links + location (e.g., `A1-x-Tech/mcp-google-calendar`, `nspady/google-calendar-mcp`, `deciduus/calendar-mcp` with 23 tools including create/update/move/delete/RSVP). None of these is Google's own first-party server — **there is no official Google-published Calendar MCP server**; all are community-maintained. If ClickUp's native Google Calendar agent-tools turn out to be read-only, one of these (self-hosted or via a hosting service) connected as a custom external MCP server (OAuth against Google) would be the fallback to get full create/update/delete-with-guests-and-Meet capability. This adds operational burden (hosting, Google Cloud OAuth app registration, credential rotation) that a 2–3-person pre-opening restaurant may not want. Sources: [github.com/A1-x-Tech/mcp-google-calendar](https://github.com/A1-x-Tech/mcp-google-calendar), [github.com/nspady/google-calendar-mcp](https://github.com/nspady/google-calendar-mcp), [github.com/deciduus/calendar-mcp](https://github.com/deciduus/calendar-mcp).

## 2. How Brandon's prototype "Founders Meeting Assistant" read/wrote Google Calendar

Per `templates/prototype/README.md` (read-only capture from the Founding Punch List, 2026-09-16): the prototype Super Agent produced a series-parent task per month plus per-occurrence child tasks, **stored the Google Calendar event instance ID and series link in the task description**, handled a Tue→Wed reschedule by rewriting text and **recreating the Thursday GCal series**, and used **Zoom** (not Meet) as the video link. It pulled "summary from last standup" but AI Notetaker notes were missing so no action items were generated.

**Assessment against the research above:** the described behavior (storing raw Google Calendar event/series IDs in a task description, and *recreating* rather than *patching* a series on reschedule) is consistent with an agent that has only **coarse-grained** calendar tools — e.g., "create event" / "delete event" primitives without a clean "update/reschedule single instance" primitive, which would explain why it deleted-and-recreated the whole series instead of moving one instance. This matches the profile of either (a) ClickUp's native Google Calendar Automations actions ("Create Event"/"Update"/"Delete" as discrete automation actions, not a rich instance-level API) rather than a purpose-built calendar MCP with instance-level RSVP/move tools, or (b) a bare-bones external MCP with only whole-event CRUD.

**UNCERTAIN — could not confirm which exact tool/integration the prototype used.** No ClickUp help article or forum post documents a native Super Agent tool that "stores GCal instance IDs in task descriptions" as a pattern — that looks like agent-authored behavior driven by its own prompt/memory rather than a documented product feature. **Recommend:** open the prototype Super Agent's profile in ClickUp (read-only) and check its **Skills → Add tools** list directly to see which Google Calendar tool source (native "Google Calendar" group vs. a connected external MCP server) is actually attached — this is the fastest way to resolve the unknown and wasn't done in this pass because it requires ClickUp UI inspection (Brandon or a workflow with UI access should check, since this research pass was WebSearch/WebFetch only, not ClickUp MCP tool calls beyond the read-only ones already used).

**Design implication either way:** if the assistant's calendar tool can't reliably patch a single recurring instance and instead deletes/recreates the whole series, the blueprint should treat "reschedule one occurrence" as a known rough edge — either accept series-recreation as the working pattern (and make sure it can't orphan guest RSVPs/Meet links when it does) or prefer Zoom (static link, survives recreation) over Meet (regenerated link) for recurring founder meetings unless testing shows otherwise.

## 3. Tasks in Multiple Lists

**CONFIRMED — plan limits are lifetime, not monthly, and do not reset on delete.** Sŏn is on **Business**, and the cited Unlimited-plan cap example is **30 combined uses of Tasks + Subtasks in Multiple Lists**, non-resetting even if the task/subtask is later deleted; reaching the cap requires a plan upgrade to keep using the feature. Business-tier's specific numeric cap was not directly stated in the sources pulled (the Unlimited figure of 30 was the only hard number surfaced) — **UNCERTAIN exact Business-plan cap**; recommend checking `help.clickup.com/.../29664799512855-Tasks-feature-availability-and-limits` directly in-app (Settings → Limits, or the article) since it returned 403 to WebFetch. Source: [help.clickup.com/.../6309958824727](https://help.clickup.com/hc/en-us/articles/6309958824727-Tasks-in-Multiple-Lists) (search snippet), [help.clickup.com/.../29664799512855](https://help.clickup.com/hc/en-us/articles/29664799512855-Tasks-feature-availability-and-limits).

**CONFIRMED — status and custom fields are shared, not independent, across a task's locations.** A task has one **"home list"** which determines which Custom Fields and Statuses apply to it; all Custom Fields tied to that home location appear in every List the task is added to. **Status is global**: changing status updates it everywhere the task appears — you cannot have a different status per list. If you move a task to a list whose status set doesn't include its current status, ClickUp prompts you to pick a new one. A live [feature request](https://feedback.clickup.com/feature-requests/p/different-statuses-for-a-task-that-is-in-multiple-lists) asking for per-list status is still open (not shipped), confirming this is still a real limitation in 2026. The suggested workaround for wanting different per-list state is task **Relationships** (linking a "reflection" task in the second list back to the home-list task) rather than multi-list membership. Source: [help.clickup.com/.../6309958824727](https://help.clickup.com/hc/en-us/articles/6309958824727-Tasks-in-Multiple-Lists), [feedback.clickup.com](https://feedback.clickup.com/feature-requests/p/different-statuses-for-a-task-that-is-in-multiple-lists).

**Fit for "Cross-Department" concept — assessment.** Given status/fields are shared and non-independent, Tasks in Multiple Lists is best suited for tasks that are genuinely *the same work item* viewed from two department Lists (e.g., a single hiring task that both Ops and Scaling People want visible in their own List), not for tagging/categorizing a task as "relevant to multiple departments" while letting each department track it independently. Since STATE.md/DECISIONS.md establish department spaces as **future-build shells** and mandate all active work stay in the **Founding Punch List** for now, a **labels/tag or a single-select "Department(s)" custom field on the one home task** (rather than actually multi-listing it into shell spaces) is the safer fit today: it avoids burning the lifetime multi-list quota, avoids accidentally surfacing a task as "active" inside a shell department space, and avoids the shared-status trap. Multi-list membership becomes more attractive later, post-funding/lease, once department spaces go live and a task legitimately needs to sit in two live Lists with one true status.

## 4. ClickUp public API (v2/v3) edit surface vs UI-only

**Custom Fields — CONFIRMED, mixed edit surface.** The API can **read and set values** for custom fields on tasks (`Get Custom Fields`, `Set Custom Field Value`), and field applicability is scoped by `custom_item_id` (task type) via each field's `applied_objects`. However: **creating new custom fields and editing a dropdown field's options is not supported via the public API** — search results explicitly note "no ability to edit/update the options of a dropdown custom field." Field *creation* itself was not confirmed as API-supported anywhere in the docs snippets pulled; ClickUp's own Custom Fields API reference page emphasizes reading/setting values on existing fields, not authoring new field definitions — treat **custom field creation as UI-only** pending direct confirmation. Source: [developer.clickup.com/docs/customfields](https://developer.clickup.com/docs/customfields), [developer.clickup.com/reference/setcustomfieldvalue](https://developer.clickup.com/reference/setcustomfieldvalue).

**Task types — UNCERTAIN, likely UI-only.** No `create`/`update` task-type endpoint was surfaced in any search; task types are referenced only as an input (`custom_item_id`) when creating/filtering tasks, not as an object you can define via API. Treat custom task type creation/editing as **UI-only** until proven otherwise.

**Statuses — UNCERTAIN, likely UI-only for status *definitions*** (creating/renaming/reordering a List/Space's status workflow), while **setting a task's current status** is a standard field on Create/Update Task. No API endpoint for defining a status set was found in this pass.

**Views — UNCERTAIN, likely UI-only.** No public API endpoint for creating/configuring Views (List/Board/Calendar/Gantt view definitions) surfaced in search; ClickUp's API v2/v3 docs focus on Spaces/Folders/Lists/Tasks/Docs/Custom Fields/Goals/Time Tracking, not View authoring. Treat as **UI-only**.

**User Groups — CONFIRMED API-editable.** `POST /api/v2/team/{team_id}/group` (**Create Group**), plus documented **Update Group** and **Get Groups** endpoints exist for User Groups within a Workspace. Note a billing side-effect: adding a guest with view-only permission to a Team/Group can auto-convert them to a paid guest seat, adding prorated cost — relevant if any blueprint automation touches guest/group membership. Sources: [developer.clickup.com/reference/createusergroup](https://developer.clickup.com/reference/createusergroup), [developer.clickup.com/reference/updateteam](https://developer.clickup.com/reference/updateteam).

**Docs with tables — CONFIRMED Claude can create these via this session's ClickUp MCP tools, without calling them.** Checked via `ToolSearch` (schemas only, no write call made, per instructions):
- `clickup_create_document` — creates a Doc given `name`, `parent` (space/folder/list/everything/workspace), `visibility`, `create_page` flag.
- `clickup_create_document_page` — creates a page inside a document, taking `document_id`, `name`, `content`, and a `content_format` parameter that explicitly accepts **`text/md`** (Markdown) or `text/plain`.
Since `content_format: "text/md"` is a first-class option, **standard Markdown tables (pipe syntax) in `content` should render as ClickUp Doc tables** — this matches how ClickUp Docs generally accept Markdown paste/import. **UNCERTAIN on edge cases**: complex table features (merged cells, column width, embedded custom-field-style content) are a ClickUp-Docs-editor construct and Markdown's plain pipe-table syntax may only get you a basic table; no source confirms rich-table-via-Markdown fidelity. Recommend a small test page (outside the Founding Punch List, read-only rules permitting) before relying on Markdown tables for anything blueprint-critical, once we're past the strict read-only phase.

**v2 vs v3 — CONFIRMED both are live; v3 is the newer, being extended for the size/timeout pain points of v2** ("ClickUp is developing API v3 to address issues with request body size and potential API timeouts"), but the search results didn't produce a clean "v3 covers X, v2 covers Y" matrix for the specific object types asked about (custom fields/task types/statuses/views/groups). **UNCERTAIN**: which objects have migrated to v3 vs remain v2-only; recommend checking `developer.clickup.com/docs/general-v2-v3-api` directly when this becomes blueprint-relevant. Source: [developer.clickup.com/docs/general-v2-v3-api](https://developer.clickup.com/docs/general-v2-v3-api) (title only, not fetched).

## 5. ClickUp AI credit costs (Business + AI add-on)

**CONFIRMED, from a third-party pricing breakdown (usecarly.com / upsys-consulting.com), cross-checked against ClickUp's own "how are Super Credits consumed" help snippets — treat exact numbers as UNCERTAIN pending a direct look at ClickUp's live pricing page, since these are secondary sources, not ClickUp's own published table:**

| Action | Cost |
|---|---|
| Super Agent run | **100–300 credits**, varies by complexity/number of steps |
| Brain chat / write / summarize / search | **0 credits** (free) |
| AI Notetaker | **Not credit-metered** — separate subscription, "from $12/mo for 60 hours," and every workspace gets 5 free admin-pooled hours that never reset |
| AI custom field (fill one field) | **10 credits** |
| Image generation (one image) | **100 credits** |
| Auto-assign / auto-prioritize one task | **10 credits** each |
| Credit price | **$0.001/credit**, sold in **$10 = 10,000-credit** blocks, pooled workspace-wide (not per-seat) |
| Brain AI add-on ($9/user/mo) monthly allowance | **1,500 credits/user/mo** |
| Everything AI add-on ($28/user/mo) monthly allowance | **5,000 credits/user/mo** |

Business plan itself is **$12/user/mo** (annual billing); stacking Brain AI (+$9) → **$21/user/mo**, or Everything AI (+$28) → **$40/user/mo**. STATE.md/DECISIONS.md note ClickUp AI is on **rollover credits** currently — worth confirming in-app which add-on tier (Brain vs Everything AI) Sŏn is actually on, since that changes the monthly allowance baseline materially (1,500 vs 5,000/user), and a single Super Agent run (100–300 credits) is a non-trivial fraction of the smaller pool. Sources: [usecarly.com/blog/clickup-ai](https://www.usecarly.com/blog/clickup-ai/), [upsys-consulting.com/en/blog/clickup-ai-pricing](https://www.upsys-consulting.com/en/blog/clickup-ai-pricing), [help.clickup.com/.../37837088720151](https://help.clickup.com/hc/en-us/articles/37837088720151-How-are-AI-Super-Credits-consumed).

**Design implication:** if the founders' meeting assistant runs multiple Super Agent steps per meeting (read calendar, check Granola, write task, maybe recreate a GCal series), a single run could burn 200–300+ credits; at 10 meetings/month across 2–3 founders that's 2,000–9,000 credits/month just for this one agent — a meaningful share of a 1,500–5,000/user pool. Recommend the blueprint budget credit usage explicitly per agent, and prefer fewer, coarser Super Agent steps over many small ones once the actual add-on tier is confirmed.
